# «Монолит Р» — сервис «КП по письму клиента»

Сервис принимает текст письма, извлекает запросы клиента и формирует черновик коммерческого предложения (КП) по исходному прайсу и справочнику доставки. Денежные вычисления выполняются кодом на `Decimal`, отдельно от LLM.

## Состав проекта

- `app.py` — локальный веб-интерфейс: вставка письма, таблица рассчитанных позиций, блок уточнений и скачивание DOCX.
- `engine.py` — загрузка прайса/тарифов, пересчёт единиц, скидка, вес, доставка, НДС и опциональный разбор через OpenRouter.
- `batch.py` — пакетная обработка папки писем с продолжением при ошибке отдельного письма.
- `documents.py` — заполнение исходного `Шаблон_КП.docx`.
- `config.py` — ставки и пороги регламента. Тарифные суммы и расстояния читаются из предоставленного `Справочник_доставки.xlsx`, а цены — из `Прайс_Монолит_Р.xlsx`.
- `letters/` — исходные 10 писем; `parsed/` — готовые разборы для автономного запуска; `results/` — сформированные JSON и DOCX.
- `tests/` — офлайн-тесты без ключа API и без обращений к сети.

## Запуск на Windows 10/11

1. Установите Python 3.11 или 3.12 с сайта https://www.python.org/downloads/ и включите опцию **Add Python to PATH**.
2. Распакуйте архив проекта в отдельную папку.
3. Откройте CMD/PowerShell в папке проекта и выполните:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\activate
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   copy .env.example .env
   ```

4. Для веб-интерфейса и разбора новых писем откройте `.env` и заполните `OPENROUTER_API_KEY`. Ключ создаётся в кабинете OpenRouter: https://openrouter.ai/keys. По умолчанию используется `openai/gpt-4o-mini`; можно поменять `LLM_MODEL`.
5. Запустите `python app.py`, затем откройте http://127.0.0.1:5000.

Без API-ключа интерфейс запустится, но разбор нового письма через LLM завершится понятным сообщением о необходимости ключа. Расчёт, тесты и пакетная обработка подготовленных JSON не требуют ключа и интернета.

## Офлайн-проверка и формирование результатов

Установите зависимости, затем из корня проекта запустите:

```powershell
pytest -q
python batch.py --no-llm
```

Первая команда запускает тесты без API и интернета. Вторая пересчитывает `parsed/letter_01.json` … `parsed/letter_10.json`, а затем создаёт `results/kp_01.json` … `results/kp_10.json` и соответствующие `.docx`. Это воспроизводимый режим проверки формул без расходов на API.

Для обработки оригинальных текстов с LLM (нужен `OPENROUTER_API_KEY` в `.env`):

```powershell
python batch.py
```

Можно указать другие входную и выходную папки:

```powershell
python batch.py --input .\letters --output .\results
python batch.py --no-llm --parsed-dir .\parsed --input .\letters --output .\results
```

Если LLM ошиблась или недоступна, обработка остальных писем продолжается; проблемы отдельных файлов записываются в `results/errors.json`.

## Архитектура (8 пунктов)

1. LLM получает письмо и актуальный перечень товаров с артикулами, наименованиями, единицами и ценами.
2. Модель возвращает JSON с контактами, пунктом доставки, запрошенными позициями и количествами; неясные позиции должны попасть в `clarify`.
3. Код проверяет артикулы по прайсу и повторно не доверяет модели в вопросах цены.
4. Количества переводятся в единицы продажи через площади/объёмы/длины/вес и округляются вверх до кратности.
5. Скидка вычисляется по общему обороту, но её база исключает акционные товары.
6. Транспорт, рейсы, тариф и возможность бесплатной доставки выбираются по таблице доставки и весу заказа.
7. Итог и выделенный НДС рассчитываются детерминированно через `Decimal`.
8. Результат сохраняется в JSON и переносится в исходный шаблон DOCX; менеджер должен проверить черновик перед отправкой клиенту.

## Важные замечания

- Результаты в архиве сформированы командой `python batch.py --no-llm` на базе `parsed/letter_XX.json`. Это fixture-разборы для стабильного офлайн-воспроизведения расчётов; во время формирования архива внешняя LLM не вызывалась, поскольку API-ключ не предоставлялся. Для новых писем доступен живой разбор через OpenRouter.
- Цены и параметры товара берутся только из исходного прайса. Если позиция неоднозначна или отсутствует, она не включается в цену и вес, а показывается в `clarify`.
- Веб-приложение является локальным черновым инструментом, не системой автоматического согласования: результат нужно проверить менеджеру.
